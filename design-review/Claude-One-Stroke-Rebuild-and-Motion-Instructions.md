# Claudeへの作業指示：全97コースの一筆書き再構築と地図演出

更新: 2026-11-14。対象リポジトリ: `walking-plan-sharing/knifefish`。この文書は実装指示であり、3件の計算候補を現地確認済みと認定するものではない。

## 目的と完了条件

旧97コースを1件ずつ調査し、同じ**歩行可能な道路・園路エッジ**を再通行しない流れに作り直す。起終点や見どころを変える必要がある場合は理由を記録する。旧経路を新A標準・B延長・C雨天と読み替えない。A/B/Cの距離目標は既存仕様（A 5〜6km、B 7〜8km）だが、往復で水増しせず自然な駅間の道を優先し、届かない場合は例外理由を残す。

完成の判定は、計算線の反復0mだけでは足りない。道路エッジ、施設入口、横断、通行可能時間、景観区間、現地記録を別々に確認し、確認できた段階だけを `routed` → `map_reviewed` → `field_verified` とする。確認できない区間に直線を引かない。船・鉄道・屋内歩行は屋外徒歩とは別レグにする。97件すべてで旧ID・旧アンカー・原ページ・旧GeoJSONを保持する。

### 各コースで実行する手順

1. **基準を凍結**：`data/routes/<slug>.geojson`、旧本文、旧経由点を読み、ハッシュと計算距離、反復位置を記録。既存の未コミット変更を保全し、旧線を消さない。
2. **根拠を集める**：自治体・公園・施設・交通機関の公式資料とOSM道路・地点を確認日付きで保存。施設ポリゴン中心を入口とみなさず、門・改札・橋・横断を個別に照合する。現地の歩行記録は今回の道を歩いた証拠と区別する。
3. **一方向の道を設計**：見どころを「点」だけでなく価値のある**道路区間と歩行方向**で選ぶ。行き止まりや橋1本の島は、本線から外す、終点を変える、別の任意行動に分ける、のいずれかを理由付きで選ぶ。元の経由点を機械的に削って魅力を失わない。
4. **計算候補を保存**：利用条件を満たす徒歩ルーターで少数ずつ計算し、エンジン・日時・経由点・出典・棄却案も保存。公開Valhallaはデモなので97件の一括実行に使わない。候補は `data/candidates/`、採用後の正本は `data/routes/` に置く。
5. **二段階で反復を検査**：GeoJSONの完全一致線分と5桁丸め線分の再通行を0mにする。続いてOSM道路エッジまたは同等の地図照合で、線が少しずれた同じ歩道の再通行も確認する。道路エッジを特定できなければ `UNKNOWN` とし、合格にしない。並行する別の歩道を同一道路と決めつけない。
6. **地点と移動種別を検査**：経由点と線のずれ、起終点、徒歩以外の区間、距離を検証する。既存の40m以内ゲートは形状との近接チェックであり、入口の正しさを保証しない。
7. **採否を記録**：旧線と新線を地図で重ね、入口、横断、水域、階段、園路、通行時間、トイレ、休憩、途中離脱をレビュー。採用・棄却理由と未確認点を `data/reviews/` または `data/research/` に残す。現地を歩いた記録がない限り `field_verified` にしない。
8. **段階的に組み込む**：採用したものだけ `data/curated/` → `scripts/build-atlas-data.mjs` → `data/catalog.json` → `atlas/data/` に反映。旧URL `#course-*`、97件、A/B/Cの意味、旧線の参照を回帰検査する。1件ずつ結果を確認してから次へ進む。

## 「線と地点を再生」を全コースで使えるようにする

再生処理は `atlas/assets/app.js` と `atlas/assets/route-playback.mjs` にあり、現在は103本のGeoJSONで停止順・始終点の機械検査を通過している。地点ごとの**具体的な説明**が入っているのはNo.47が中心で、旧97件の無名経由点には「未照合」と表示する。これを架空の説明で埋めない。

- 新経路の各経由点には安定した `id`、名称、実座標、入口と区別した `source`、短い `description`、根拠URL・確認日を付ける。`routeText` の矢印順を座標に機械割当しない。候補線と40m超離れる地点は吹き出しを出さず、画面に除外数を表示する。
- 吹き出しは「何が見える／なぜ寄る／未確認の条件」を1〜2文で書く。展示・開館・料金は変わるので確認日と出発前の再確認を示す。駅の出口が未確定なら「駅付近」とする。
- 再生ボタンはユーザー操作時だけ動かす。線描画は距離に応じ約9〜20秒、地点では約2.2秒停止。選択・変種切替・画面移動・「すぐ表示」で前の再生を確実に止める。線がないC案はボタンを無効化する。
- 地図なしでも候補・距離・説明を読めるようにする。`prefers-reduced-motion` では線を即時表示し、地点説明はクリックとキーボードで読めるようにする。読み上げ用の状態表示も確認する。
- 97件の説明が揃ったと主張する前に、全コースで「名称と説明の根拠」「線上への配置」「表示順」を検査し、PCとスマートフォンで吹き出しの見切れ・連続操作・中断を目視確認する。

## コース選択から地図展開へ：追加アニメーション案

**演出名：カードから道へ。** 選んだカードの色帯が地図上の始点の光へつながり、地図が開いて道が現れる。選択の結果を分かりやすくする短い演出で、長いチェックポイント再生は自動開始しない。

1. カード選択から0〜160ms：選択カードを `transform: translateY(-3px) scale(1.01)` と影・アクセント線で強調。非選択カードは軽く彩度を落とす。フォーカスは選択カードに保持。
2. 120〜520ms：地図パネルに `opacity` と `transform` のみを使う柔らかな展開。PCではカード側から地図へ視線が移るように薄い光の軌跡を一回流す。スマホでは一覧から地図へスクロールして上部の地図を展開し、シートの角をわずかに開く。`clip-path` は性能と見切れを実機で確認できた場合だけ使う。
3. 地図が表示された後、始点リングを約300ms脈動させ、候補線を約900〜1400msで描画。終点で小さく収束し、コース名・距離・確認状態をクロスフェードする。道路の線を補間して別の道へ変形させず、別形状への切替はフェードで行う。
4. ローディング中・地図ライブラリ失敗時はカードと説明を即時表示。旧リクエストが遅れて戻っても `routeRequest` で無視し、前の演出とタイマーを中断する。ユーザーが地図をドラッグ中はカメラを自動移動しない。
5. `prefers-reduced-motion` では展開・光・線描画・自動スクロールを省き即時表示。`aria-live` で選択結果と距離・確認状態を通知。キーボード選択でも同じ情報が得られるようにする。

受け入れの目安は「選択から主要情報表示まで待たせない」「演出は約1.5秒以内」「連続選択・A/B切替で線や吹き出しが残らない」「スマホで地図とシートが重なって操作不能にならない」。CSSは `transform` と `opacity` を基本にし、地図の `invalidateSize()` はレイアウト完了後に一度だけ呼ぶ。

```powershell
node scripts/build-atlas-data.mjs
node scripts/package-atlas.mjs
node scripts/build-rebuild-worklist.mjs
node scripts/build-retrace-clusters.mjs
node scripts/build-one-stroke-targets.mjs
```

候補の再計算が必要な場合だけ `node scripts/build-one-stroke-examples.mjs No.17` のように1件ずつ実行する。全件一括のデモAPI実行はしない。提出時は各コースの旧・新GeoJSON、距離、完全一致と丸め形状の反復、道路エッジ照合の結果または `UNKNOWN`、除外した地点、根拠、未確認事項、PC/スマホの画面、採用状態をまとめる。公開は旧ページと旧URLの回帰確認、画面の目視確認後に段階的に行う。
